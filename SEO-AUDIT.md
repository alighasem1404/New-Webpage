## Success target

The practical target for this landing page is **85+ before launch** and **90+ after live validation**. A perfect score is unnecessary. Ranking will still depend on competition, authority, links, product demand, and the usefulness of future book and article pages.

## Phase 1 — Fix performance and rendering

Priority: critical. This phase should produce the largest score improvement.

### 1. Defer the PDF preview system

- [ ] Remove the top-level PDF library import from the page’s main module.
- [ ] Load PDF.js, its worker, the page-flip library, and the 9.01 MB PDF only after the preview is requested or is close to the viewport.
- [ ] Render only the first spread initially; render additional pages on demand.
- [ ] Avoid cloning every high-resolution canvas for the modal.
- [ ] Keep an ordinary HTML title and description beside the preview so its meaning never depends on canvas content.

**Done when:** the PDF, PDF worker, and page-flip code do not appear in the initial page-load network requests.

### 2. Optimize images

- [ ] Convert large PNG photography/artwork to appropriately compressed WebP or AVIF.
- [ ] Generate responsive image widths and use `srcset` and `sizes` for hero, campaign, about, newsletter, and article imagery.
- [ ] Keep the final above-the-fold LCP image eager and discoverable in the original HTML.
- [ ] Add `loading="lazy"` and `decoding="async"` to below-the-fold images.
- [ ] Add intrinsic `width` and `height` attributes to every content image.
- [ ] Replace the 12.97 MB campaign image before production.
- [ ] Confirm that duplicate uses of an image reuse the same optimized URL.

**Done when:** below-the-fold images are not requested during the initial viewport load, every image reserves its layout space, and there are no multi-megabyte display images.

### 3. Make primary content independent of heavy JavaScript

- [ ] Put real project titles, summaries, rules versions, and image markup directly in `index.html` or server-render them.
- [ ] Use JavaScript only to enhance filtering, rotation, and interaction.
- [ ] Ensure a PDF failure cannot prevent project content or other page behavior from loading.
- [ ] Test the page with JavaScript disabled and confirm that the title, main copy, projects, about content, and newsletter explanation remain readable.

**Done when:** all indexable commercial content exists in the initial HTML and remains present if optional scripts fail.

### 4. Remove prototype-only markup

- [ ] Choose one production hero and leave it visible in the original HTML.
- [ ] Keep exactly one H1 in the production source.
- [ ] Keep one newsletter section and remove the unused variants.
- [ ] Remove the visible “TEST ONLY” project control and hidden typography panel.
- [ ] Remove unused variant CSS and JavaScript after the final design is selected.

**Done when:** page content does not visibly switch after the main script loads and no test controls or inactive content variants remain in production.

**Expected score after Phase 1: approximately 73–76 / 100**, subject to live speed measurements.

This is a production roadmap, not a criticism of broken links in the prototype.
